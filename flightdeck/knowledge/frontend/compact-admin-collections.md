# 紧凑后台集合

用户在 Gallery 和 Blog 验收确认的默认设计，适用于管理后台的内容、分类、标签、评论、审核和治理集合。

## 标题与工具

使用 `ManagePage` / `PageHeader` 的 `tools` 插槽与 `CollectionHeaderTools`。宽屏标题左侧，搜索、筛选、排序、视图组右侧；主操作只有一个，窄屏保持标题右侧，工具下一行。控件视觉高度统一 36px，不按手机断点放大。不要复制页面 CSS、Teleport 或 DOM 查询来移动工具。

标题栏只为实际存在的主操作渲染操作列；没有 actions 插槽或插槽内按钮因权限而未渲染时，工具组贴齐内容区右侧，不保留空列或列间距。

筛选和排序使用按钮打开弹窗，先编辑草稿，点击应用才提交；取消不改变查询。没有业务筛选项就不显示空筛选按钮。表格列可继续排序，与弹窗共享同一查询状态；不得同时常驻排序下拉和方向按钮。视图组使用中性默认 Surface，选中项有品牌软背景与 `aria-pressed`。

只有筛选、没有搜索能力的集合使用 `CollectionHeaderTools` 的 `:searchable="false"`，不添加无效搜索框。搜索默认开启；Vue 可选布尔 Prop 应显式声明默认值，防止省略属性时意外关闭搜索。

集合启用 `externalControls` 保留选择、批量操作和活动筛选，隐藏重复工具。网格不显示表格列标题和列表排序行。分页、搜索、筛选重置和查询序列化由产品原有 Workflow 负责。

## 网格

`CollectionPanel` 默认紧凑网格：宽容器以 12rem 为最小卡宽 auto-fill，窄容器约 9rem。随空间增加列数，不把4K固定为三列。卡片选择框不增加背景块、阴影和额外内边距。长标题截断，常用操作仍可键盘访问。

## 分页

统一使用 `CollectionPaginationBar` 或 CollectionPanel 默认分页。左侧选择器显示“20 条 / 页”“15 篇 / 页”，右侧依次为首页、上一页、有限页码与省略号、下一页、末页。按钮视觉尺寸28px，图标两轴居中；小屏允许整组换行，但不能裁切或生成100个页码。不再显示“显示1–24，共105条·共5页”等范围统计，也不单列“每页”文字。

真实total来自服务端或实际筛选集合。每页数量必须在产品允许选项中；切换数量/筛选回第一页，删除缩小集合后校正页码。层级集合先构建完整排序树，再对显示结果分页；不要把树列表强制锁在第一页。不能用仅拉取第一页的数据推断总数。

## 评论

使用 `CommentModerationCollection layout="columns"` 与 `CommentModerationToolbar`。作者、访客标识和时间在主列上方，正文在下方；桌面右侧依次对齐来源、状态、横向三点菜单。完整显示状态，包括已通过；不展示来源缩略图。通过审核放入更多菜单，回复上下文、用户详情、批量操作和分页保持共享。窄屏将来源、状态和菜单移到正文下方，不横向裁切。工具栏贴齐内容区右边缘，不能因父工具区更宽而留下空白。公开评论和审核权限不因布局变化而改变；产品仅提供资料、上下文和操作 Adapter。旧 compact/table 仅保留显式调用能力，新接入遵循 columns。

## 验收与发布

至少使用 CLI Playwright 验证390/1440宽度；网格补4K，分页补多页/100页、首页末页、每页数量变化。检查SSR、长标题、空态、选中态、排序和取消操作，不仅检查组件import。测试夹具与真实服务结果分开记录。

本地源码覆盖通过不等于线上生效。部署必须使用独立候选包与lock构建，校验制品，确认运行版本和真实页面。共享库默认值更新后仍须查找产品私有分页、Dock、网格CSS和旧工具栏，逐项迁移，不能只升级依赖就声明全站完成。
